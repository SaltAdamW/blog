# 开发文档

本文件是 `agent-research-weekly` 的开发入口。任何代码、配置、调度、归档或发布流程变更，开始修改前必须先输出一次“开发封层”。

## 开发封层门禁

开发封层不是泛泛计划，而是本次变更的边界冻结。输出至少包含：

```text
开发封层
- 目标：本次要改变的用户可见行为
- 不做：明确不触碰的行为、数据和发布边界
- 层级：本次修改属于哪一层
- 允许修改：具体文件或模块
- 禁止越界：不能顺手修改的相邻层
- 验证：要运行的测试、编译或回归检查
- 完成条件：什么结果才算完成
```

没有封层时，不进入实现；需求发生变化或发现必须跨层时，先重新输出封层并说明原因。

可用命令生成标准模板：

```bash
cd /root/agent-research-weekly
python3 -m research_weekly dev-layer
```

命令只输出模板，不写文件、不调用模型、不执行发布。

## 系统分层

按依赖方向从下到上划分：

| 层 | 名称 | 职责 | 典型文件 |
| --- | --- | --- | --- |
| L0 | 基础安全与通用工具 | URL 安全、文件原子写入、锁、命令执行、时间和哈希 | `core.py`, `fetch.py` |
| L1 | 采集与证据 | RSS、网页、PDF、候选来源、原文快照和证据块 | `fetch.py`, `discovery.py` |
| L2 | 研究与判定 | 搜索、候选筛选、事实核读、经验准入、站点质量排序 | `codex.py`, `source_quality.py` |
| L3 | 内容工作流 | 周报、长文、框架确认、分节写作、追问审稿 | `pipeline.py`, `article.py`, `questioning.py` |
| L4 | 发布与恢复 | bundle 校验、发布台账、Git worktree、线上回读、重试 | `publish.py`, `article_publish.py` |
| L5 | 入口与调度 | CLI、systemd、doctor、配置加载和运行编排 | `cli.py`, `__main__.py`, `config*.json` |
| L6 | 本地材料与归档 | 草稿、研讨材料、运行报告、私有证据和索引 | `drafts/`, `var/`, `review-policy.md` |

## 变更规则

1. 先确定最小所属层；只有当接口契约确实需要时才跨层。
2. L0/L1 变更必须检查安全边界、失败恢复和已有证据哈希。
3. L2 变更必须区分搜索线索、已读原文和发布证据，不能用评分替代核读。
4. L3 变更必须保留人工确认、追问审稿和断点续跑门禁。
5. L4 变更不得绕过发布前审稿、远端校验或用户改动保护。
6. L5 变更必须验证旧命令兼容性和定时器内容；不要在普通开发中启用真实发布。
7. L6 归档默认使用副本和索引，禁止删除或改写冻结运行材料。

## 标准开发流程

1. 输出开发封层。
2. 阅读本文件、`AGENTS.md` 以及受影响层的代码和测试。
3. 先补或调整针对行为的测试，再做最小实现。
4. 运行受影响测试、`compileall`，再运行完整测试集。
5. 检查 `git diff`、未纳入的文件、路径和运行产物，确认没有越过封层。
6. 汇报变更、验证结果、未解决风险和是否需要重新封层。
